# قواعد تأليف المهارة في قُدرة (Skill Authoring Rules)

> مصدر الحقيقة لتصميم أي مهارة. مبني على طالب القدرات السعودي (ثانوي) وعلى قرارات المنتج.

---

## 0) قبل أن تبدأ أي مهارة — حدود العنوان (إلزامي)

**لا تكتب سطراً واحداً في مهارة جديدة قبل هذه الخطوة.**

1. افتح [`docs/KAMI_SKILLS_ROADMAP.md`](./KAMI_SKILLS_ROADMAP.md) واقرأ **عناوين كل المهارات** في المجال الحالي والمجالات المجاورة.
2. افتح المهارات المنشورة في `src/content/` وقارن `title_ar` / `id` / `hook_ar`.
3. اسأل: *هل هذه الجملة أو المثال أو المصيدة تنتمي لعنوان مهارة أخرى؟*  
   إن نعم → **احذفها من هنا**. اتركها لتلك المهارة فقط.
4. هذه المهارة تشرح **عنوانها فقط**. لا «تلمّح» لمهارات قادمة، ولا تدرّب عليها داخل `drill` / `final_extra` / التصوّر / الاختصار.

### أمثلة حدود صارمة

| هذه المهارة | مسموح | ممنوع (ينتمي لعنوان آخر) |
|-------------|--------|---------------------------|
| التغيّر المئوي | من → إلى، نسبة الزيادة/النقص، مصيدة القسمة على الجديد | زيادة ثم نقص متتالية → `successive-percent` |
| النسب والتناسب | تقسيم بنسبة أ:ب، تناسب طردي بسيط داخل نفس النمط | ربح٪ وخصم٪ كموضوع مستقل → `buy-sell` / الربح والخصم |
| النسب المتتالية | عامل×عامل، صافي التغيّر بعد عمليتين | إيجاد نسبة تغيّر واحدة فقط → `percent-change` |
| المتوسط | مجموع ↔ متوسط ↔ عدد ناقص | احتمال سحب من كيس → مهارة احتمال |
| مساحة المثلث | ½×ق×ع | فيثاغورس لإيجاد ضلع → `pythagoras` |

### قائمة تحقق قبل الكتابة

- [ ] راجعت عناوين خريطة المهارات + المهارات الموجودة  
- [ ] حدّدت جملة واحدة: «هذه المهارة تعلّم ____ ولا تعلّم ____»  
- [ ] لا سؤال في البنك يُحلّ بنمط عنوان مهارة أخرى كفكرة أساسية  

---

## 1) هدف المهارة

المهارة تعلّم **نمط حساب واحد** يظهر كثيراً في القسم الكمي، عبر:

1. **تصوّر** يُحرَّك باليد  
2. **اختصار** يُستخدم تحت الوقت  
3. **ثلاثة تدريبات** متدرجة: دقة → توازن → سرعة  

الطالب يريد: *أفهم بسرعة → أحلّ أصح → ثم أحلّ أسرع*.

---

## 2) الدقة الرياضية (خط أحمر)

- **أي معلومة رياضية خاطئة ممنوعة منعاً باتاً.** لا تخيّل أرقامًا ولا تختلق نتائج.
- كل سؤال يُحلّ **مرتين مستقلتين** قبل الاعتماد (ورقة أو آلة حاسبة).
- كل رقم في التصوّر / المثال / الاختصار / الملخص يجب أن يطابق الحساب.
- إن تعارض نص مع رقم: أصلِح المصدر فوراً، لا تُمرّر المهارة.
- **صيغة السؤال والإجابات سليمة:** وحدات واضحة، لا رموز مبهمة بلا شرح، لا خيارات مكررة المعنى.

---

## 2.1) الأسئلة — إبداع بلا هلوسة

- اجعل السؤال **مبدعاً قدر الإمكان**: سياق حيّ يفتح ذهن الطالب (سعر، مباراة، شحن، خريطة، راتب، عرض…) لا قالب «عدد زاد من a إلى b» في كل مرة.
- الإبداع = سياق + مصيدة ذكية + فكرة النمط. **ليس** اختراع قوانين أو أرقام خاطئة.
- حافظ على نفس المهارة فقط — لا تُدخل أنماطاً أخرى في بنك هذه المهارة.

---

## 2.2) اختيار من متعدد (QCM) — إجابة صحيحة واحدة فقط

- أربع خيارات، و**خيار صحيح واحد لا غير**.
- قبل الاعتماد: تحقّق أن **لا يوجد خياران بنفس المعنى** (مثال ممنوع: «بدون تغيّر» و«زيادة 0٪» معاً).
- باقي الخيارات = مصائد شائعة حقيقية (قسمة على الجديد، جمع النسب، عكس النسبة…).
- `correct_index` يجب أن يطابق الحساب بعد الحل المزدوج — لا تخمين.

---

## 3) سهولة الفهم (حتى لأضعف مستمع)

- كل جملة قصيرة، مباشرة، بلا زخرفة.
- **الملخص (بعد التدريب) خاصة:** أبسط لغة في المنتج كله.
- عند الرموز (`÷` `×` `−` `%` `:`):
  - اكتب المعنى بالكلمات بجانب الرمز مرة على الأقل في الملخص.
  - مثال جيد: «٢٠ تقسيم ٨٠ = ٠٫٢٥ أي ٢٥٪»
  - مثال سيئ: «Δ/base → %» أو جملة محشوة رموزاً بلا شرح
- ممنوع افتراض أن الطالب يتذكر مصطلحاً لم يُعرَّف في نفس الشاشة.

---

## 4) اللغة والنبرة

### 4.1 داخل المهارة

- **فصحى حديثة فقط. صفر لهجة.**
- لا «وش / يلا / تمام / مو / ليش / تبي / عشان…» داخل `/skill/[id]`.
- **صفر حروف لاتينية في أي نص يراه الطالب** (تصوّر، اختصار، أسئلة، خيارات، حلول، ملخص، محاكاة، نهائي):
  - ممنوع: `a/b`، `x:y`، `n²`، `A+B`، `π` كرمز لاتيني/يوناني في الجملة…
  - استخدم عربياً: أ/ب، س:ص، ن²، كمية أ، باي…
  - الأرقام الغربية (0–9) والرموز الحسابية (`+ − × ÷ = ٪ √`) مسموحة.

### 4.2 اللهجة في كامل التطبيق (٣ جمل فقط — الرئيسية)

| الجملة | الموقع | لماذا |
|--------|--------|--------|
| **حرّك. وش يصير؟** | فوق تصوّر الرئيسية | فضول + لمس فوري |
| **يلا نبدأ** | زر أول زيارة | دفعة بدء خفيفة |
| **تمام.** | بعد سؤال الرئيسية الصحيح | إقرار ندّ قصير |

### 4.3 ممنوع

- تشجيع فارغ («ليست ضعفاً فيك»، «يا سلام»، «لا بأس»…).
- عند الخطأ: «خطأ» + سبب عملي في **الملخص فقط**.

---

## 5) التصوّر التفاعلي

### 5.1 قبل التصوّر — نص الاستخدام

سطران فوق الـ viz:

1. كيف تستخدمه (اسحب / اضغط ماذا)  
2. ماذا ستلاحظ (بدون شرح القانون)

### 5.2 التفاعل

- ممنوع الاعتماد على `range` وحده.
- سحب مباشر على الشكل أو فاصل أو آلة واضحة + presets للموبايل.
- لمس ≥ 44px، صفر تداخل نصوص، ارتفاعات ثابتة أو SVG صريح.
- أرقام `dir="ltr"` + `tabular-nums`.

### 5.3 المصيدة في التصوّر

اختيارية بزر («أظهر المصيدة») بعد أن يحرّك الطالب.

---

## 6) الاختصار + هدف الوقت

### 6.1 صندوق الاختصار

- جملة واحدة + ٢–٣ خطوات + مثال رقمي صحيح.
- لغة اختبار عملية.

### 6.2 مقياس الوقت (إلزامي — عرض جميل)

كل مهارة لها أهداف زمنية **خاصة بها** حسب ثقل النمط (ليست أرقاماً ثابتة لكل المهارات):

| المستوى | المعنى | مثال مهارة خفيفة | مثال مهارة أثقل |
|---------|--------|------------------|-----------------|
| ممتاز | اختصار متقن | ≤ ١٨ ث | ≤ ٢٦ ث |
| جيد | جاهز للإيقاع | ≤ ٢٨ ث | ≤ ٣٦ ث |
| مقبول | داخل ضغط الاختبار تقريباً | ≤ ٣٨ ث | ≤ ٤٨ ث |
| بطيء | يحتاج تمريناً | ≤ ٥٢ ث | ≤ ٦٣ ث |
| ضعيف | أبطأ من إيقاع آمن | فوق البطيء | فوق البطيء |

قواعد ضبط الأرقام:

- الأرقام تُشتق من صعوبة النمط (خطوة واحدة أسرع من عوامل متتالية).
- لا تضع «ممتاز» سريعاً جداً فيُرهق الطالب، ولا مرتاحاً جداً فيُخدَع.
- المرجع الذهني: الاختبار ≈ ٦٣ث/سؤال؛ هدف المهارة أسرع لأن النمط معروف بعد الاختصار.
- `trick_ar.time_target_sec` = نفس `timing.excellent_sec`.

يُعرض المقياس في صفحة المهارة بأرقام **هذه** المهارة فقط.

---

## 7) التدريب — مسار من 3 تدريبات + اختبار نهائي

بعد التصوّر والاختصار:

1. **ثلاثة تدريبات** (دقة → توازن → سرعة)  
2. **اختبار نهائي مقفول** حتى تُنجَز التدريبات الثلاثة كلها مرة واحدة على الأقل  

### 7.1 أهداف الجولات

| الجولة | التركيز | أسئلة | هدف الوقت الكلي |
|--------|---------|-------|------------------|
| **١** | الصحة فقط | 6 من بنك 18 (خلط) | `ok_sec × 6` |
| **٢** | صحة + وقت | 6 مخلوطة جديدة | `good_sec × 6` |
| **٣** | صحة + سرعة | 6 مخلوطة جديدة | `excellent_sec × 6` |
| **٤ نهائي** | محاكاة اختبار المهارة | **25** = 18 + 7، مخلوطة | مؤقت واحد ≈ دقيقة/سؤال · بلا تصحيح أثناء الحل · تنقّل حر |

- كل دخول يعيد **خلط** ترتيب الأسئلة — ممنوع ترتيب ثابت.  
- بعد كل جولة احفظ النتيجة والوقت، واعرض تحدياً لإعادة المحاولة (لا تكتب «أتممتها»).  
- النهائي CTA بارز ومقفول حتى تكتمل ١ و ٢ و ٣.

### 7.2 أثناء السؤال

- بعد الاختيار: **صحيح** أو **خطأ** فقط + التالي.
- لا حل أثناء السلسلة.
- مؤقت من مقياس المهارة + هدف الجولة الكلي ظاهر في رأس التدريب.
  - جولة ١: طول ≈ `slow_sec` · هدف سؤال ≈ `ok_sec`
  - جولة ٢: طول ≈ `ok_sec` · هدف ≈ `good_sec`
  - جولة ٣ / ٤: طول ≈ `good_sec` · هدف ٣ ≈ `excellent_sec`، هدف ٤ ≈ `good_sec`

### 7.3 ملخص الجولة (إلزامي وسهل جداً)

لكل سؤال اعرض **دائماً** (حتى لو اختار الطالب الإجابة الصحيحة):

1. اختيار الطالب  
2. الإجابة الصحيحة  
3. **الطريقة الكاملة للحل** (`solve_ar`)  
4. **زمنه** — دائماً  
5. **ملاحظة المستوى الزمني** — **فقط إن كانت الإجابة صحيحة**  

لا تعرض «سبب الغلط الشائع». في نهاية الملخص: أعد الجولة / التالي / النهائي إن فُتح / مسار التدريب.

### 7.4) مراجعة «بنظرة الطالب» بعد إنشاء أي مهارة

بعد الانتهاء من كتابة المهارة، مرّ عليها كأنك طالب:

1. التصوّر: هل يتحرك؟ هل النص فوقه واضح؟ هل الأرقام صحيحة؟  
2. الحدس + الاختصار + المثال: هل الحساب يطابق؟ هل اللغة سهلة؟  
3. مقياس الوقت: هل أرقام **هذه** المهارة منطقية؟  
4. **كل سؤال** في `drill` و `final_extra`: حلّه → `correct_index` → خيار واحد صحيح → `solve_ar`  
5. مسار التدريب + قفل النهائي + إعادة التحدي  
6. أصلح أي خطأ قبل الاعتماد

## 8) بنية ملف المهارة

```ts
Skill {
  id, title_ar, hook_ar, estimated_minutes, icon, visual,
  intuition_ar,
  trick_ar: { statement, steps, example_ar, time_target_sec },
  timing: {
    excellent_sec, // ممتاز
    good_sec,      // جيد
    ok_sec,        // مقبول
    slow_sec,      // بطيء (فوقه = ضعيف)
  },
  drill: Question[],        // 18 سؤالاً — عيّنة 6 لكل من التدريبات ١–٣
  final_extra: Question[],  // 7 أسئلة — النهائي = drill + final_extra = 25
  review_status...
}
```

## 9) قائمة تحقق «جاهزة»

- [ ] راجعت عناوين المهارات الأخرى وحدود العنوان (القسم 0)  
- [ ] صفر حروف لاتينية في نصوص الطالب (قسم 4.1)  
- [ ] صفر أخطاء رياضية / صفر هلوسة أرقام  
- [ ] أسئلة مبدعة ضمن النمط فقط  
- [ ] كل سؤال: إجابة صحيحة واحدة فقط  
- [ ] `solve_ar` كامل ويُعرض حتى بعد الصحة  
- [ ] `drill` = 18 و `final_extra` = 7  
- [ ] مسار: تحدي بالدرجة/الوقت، خلط كل مرة، نهائي مقفول ثم CTA قوي  
- [ ] مراجعة بنظرة الطالب تمت

## 10) خريطة المهارات

المصدر: [`docs/KAMI_SKILLS_ROADMAP.md`](./KAMI_SKILLS_ROADMAP.md) — خمسة مجالات، حساب = 16، والباقي ≥ 10 لكل مجال.

المنشور حالياً في التطبيق يُحدَّد عبر `ALL_SKILLS`؛ الباقي يظهر في واجهة المهارات كـ «قريباً».
